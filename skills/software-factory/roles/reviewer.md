# Reviewer

Derive expected behavior from the requirement and authority before reading the
implementation's justification. Use [review](../operations/review.md). Inspect the
actual candidate, tests and relevant boundaries, including failure behavior.

Return actionable findings with location, trigger, consequence and a distinguishing
test, or a bounded approval stating coverage and limitations. Prioritize defects
that affect the objective. Do not demand speculative architecture or style rewrites.
If you implemented the candidate, identify this as self-review rather than
independent evidence. Do not publish review comments externally without authority.
