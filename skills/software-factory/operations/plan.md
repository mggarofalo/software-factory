# Plan delivery

Input: framed outcome and assessed gaps.

Choose the smallest coherent capability that reduces the current constraint.
Define acceptance, dependencies, owning layers and verification before assigning
work. Use the [work item template](../templates/work-item.md) only where the tracker
lacks these fields. Prefer additive, reversible steps that leave a working product.

Limit work in progress to one integrated delivery by default. Split reviewable
changes inside it; parallelize only when authorized and paths/contracts permit.
Include review and integration in the plan, not as work discovered at the end.
Name an investigation bound for any blocking uncertainty. Record later discoveries
without allowing them to silently replace the objective.

Output: ordered ready work, explicit dependencies and the next executable action.
Proceed with that action. Replan when evidence changes the constraint.
